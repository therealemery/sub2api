# OwnAPI PackyAPI 文本与 DC-API MiniMax H3 实施计划

> 设计依据：`docs/superpowers/specs/2026-09-04-ownapi-packyapi-dcapi-upstreams-design.md`

## 实施原则

- 先测试后实现；不写入真实上游密钥。
- 尽量复用现有 `AccountTypeUpstream`、OpenAI 网关、渠道模型映射、API Key 鉴权、余额扣费和账号调度。
- PackyAPI 与 DC-API 使用不同的平台/能力标记和模型白名单，路由层做硬隔离。
- 后台凭证只存后端，API 返回继续脱敏。

## 阶段 1：账号与配置模型

1. 检查并扩展账号平台/类型校验，使管理员可以创建：
   - PackyAPI OpenAI 兼容文本账号；
   - DC-API MiniMax H3 视频账号。
2. 为账号凭证增加受控配置字段：`base_url`、`api_key`、`model_mapping`、上游类型和能力标记。
3. 保持数据库兼容，优先使用现有 JSON 凭证和 `extra` 字段；只有现有字段无法表达时才新增迁移。
4. 确保账号列表、详情、导出和错误响应都不会泄露完整密钥。
5. 补充账号创建/编辑/脱敏测试。

## 阶段 2：PackyAPI 文本路由

1. 将 PackyAPI 账号接入现有 OpenAI Chat Completions 转发器。
2. 在渠道模型映射中记录 OwnAPI 模型 ID 到 Packy 模型 ID 的精确映射。
3. 调度时只选择绑定客户 OwnAPI 分组、平台为 OpenAI、具备文本能力且允许该模型的 Packy 账号。
4. 转发请求时覆盖 Authorization 为服务端 Packy Key，禁止透传客户 OwnAPI Key。
5. 保持流式/非流式 usage 收集、现有失败转移和 USD 客户扣费路径。
6. 补充路由选择、请求头替换、模型映射、失败不扣费和流式 usage 测试。

## 阶段 3：DC-API MiniMax H3 视频路由

1. 根据 DC-API 官方接口定义确定任务创建、参考图、时长、分辨率和任务查询所需字段；将上游字段映射到内部请求结构。
2. 新增独立视频端点和 handler，沿用 OwnAPI API Key 鉴权、分组权限、并发限制和运维日志。
3. 调度时仅选择 DC-API 视频账号和 `MiniMax H3` 映射，Packy 账号永不参与。
4. 使用 DC-API Key 替换客户 Authorization；清理上游响应后返回任务 ID、状态和媒体地址。
5. 设计任务状态持久化/轮询接口；对创建失败、限流、超时和无效响应做不扣费处理。
6. 补充提示词、参考图、时长、分辨率映射及响应清理测试。

## 阶段 4：控制台与前端

1. 在账号管理创建/编辑表单中增加上游用途选择和对应字段提示。
2. Packy 表单显示文本模型映射；DC-API 表单显示 H3 视频能力和参数配置。
3. 在视频生成页面增加提示词框、参考图上传、时长、分辨率和任务状态展示。
4. 所有前端请求只携带 OwnAPI 会话/客户 Key，不读取或展示上游凭证。
5. 补充中英文文案、表单校验、上传大小/格式限制和错误提示。

## 阶段 5：计费、成本与验证

1. 文本和视频均使用 OwnAPI USD 客户价格及现有分组倍率。
2. Packy 成本和 DC-API 成本分开记录；不改变客户余额扣费来源。
3. 增加幂等结算、失败不扣费、账号成本和利润统计测试。
4. 运行后端单元/集成测试、前端类型检查、Lint 和构建。
5. 使用本地测试上游模拟器验证：一条文本非流式、一条文本流式、一条 H3 视频创建/查询链路。
6. 真实 Packy/DC-API Key 只在用户确认后通过本地控制台录入，再进行低风险端到端测试。

## 阶段 6：发布

1. 提交并推送实现分支到 `main` 前先检查 diff、迁移和密钥泄露。
2. GitHub Actions 构建部署后验证 `/health`、文本模型调用、视频任务创建和客户扣费。
3. 记录部署版本、回滚镜像和上游配置位置，不在仓库记录任何密钥值。
